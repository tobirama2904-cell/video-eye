# video-eye — бесплатный «глаз» для агента, без лимитов и без ключей

Задача: агент **реально смотрит видео** (кадры + речь) и отвечает по содержанию, а не по названию.
Всё бесплатно: никаких API-ключей, никаких платных подписок, **никакого Hugging Face**.
Единственный ресурс, который нужен — GitHub-аккаунт (он у вас уже есть).

## Как это устроено

```
┌──────────────────────────── ПЕСОЧНИЦА АГЕНТА (2 ядра, 1.9 ГБ RAM) ───────────────────────────┐
│  1. yt-dlp качает видео            (тут YouTube открыт)                                      │
│  2. ffmpeg делает кадры            (дёшево: 30–100 jpg с таймкодом в имени)                   │
│  3. ffmpeg делает audio.opus       (24 кбит/с — час видео ≈ 11 МБ)                            │
│  4. всё это уезжает в GitHub Release (транспорт)                                              │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
                                        │
┌───────────────────────────────────────▼───── GITHUB ACTIONS (4 vCPU, 16 ГБ RAM) ─────────────┐
│  5. Whisper (веса с CDN OpenAI — не HF) → транскрипт с таймкодами                              │
│  6. Ollama + VLM (реестр Ollama — не HF) → подпись каждого кадра                              │
│  7. report.md + transcript.md + sheet.jpg → коммит обратно в репозиторий                      │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```
Публичный репозиторий → **минуты Actions не ограничены** (стандартный раннер 2–4 vCPU / 16 ГБ).
Приватный → 2 000 бесплатных минут в месяц на плане Free.

## Почему так, а не «просто запустить на раннере»

YouTube блокирует IP-адреса дата-центров: на раннере GitHub **все** клиенты yt-dlp получают
`Sign in to confirm you're not a bot` (проверено: default, android, ios, web_safari, mweb, tv,
android_vr, web_embedded, tv_simply, `--force-ipv4`, `player_skip=webpage`). Публичные зеркала
Piped мертвы (526), у большинства Invidious 401–403. Поэтому скачивание делает песочница,
а раннер занимается только вычислениями.

## Использование

```bash
export GH_TOKEN=<token with repo + workflow scopes>
cd video-eye

python3 gh_runner.py push                    # синхронизировать репозиторий

# полный конвейер: скачать локально → посчитать на бесплатном раннере → забрать отчёт
python3 gh_runner.py analyze --url "https://youtu.be/XXXX" \
      --frames 80 --width 1024 --whisper small --caption moondream --wait

python3 gh_runner.py fetch                   # report.md, transcript.md, sheet.jpg, кадры
python3 gh_runner.py status                  # список прогонов
python3 gh_runner.py prune --keep 5          # подчистить старые релизы с ассетами
```

Ручной запуск без песочницы — во вкладке **Actions → watch** (нужен `asset_tag` из релиза
или прямой URL на медиафайл, который раннер может скачать сам).

### Модели

| Задача | Модель | Откуда веса | Время на 3-мин видео |
|---|---|---|---|
| Транскрипт | Whisper `tiny…large-v3` (openai-whisper) | `openaipublic.azureedge.net` | small ≈ 1 мин |
| Подписи кадров | `qwen2.5vl:3b` (рекомендуется) / `moondream` / `llava:7b` (Ollama) | `registry.ollama.ai` | qwen2.5vl ≈ 30–50 с/кадр на CPU, moondream быстрее, но зацикливается |

**Проверенные режимы.** `--caption off` (только Whisper): 3-минутное видео → ~2 минуты на раннере.
`--caption qwen2.5vl:3b`: +25 минут на 30 кадров. Для часовых видео разумнее `off`, а кадры
читать самому (или гнать VLM по выбранному окну через `--start/--end`).

## Что получается

- `report.md` — метаданные, главы, **подписи каждого кадра от VLM**, полный транскрипт с таймкодами, индекс кадров
- `transcript.md` — только речь, построчно с таймкодами
- `frames/*.jpg` — кадры с таймкодом в имени (агент читает их как изображения)
- `sheet.jpg` — контактный лист (сетка кадров одним файлом)
- `info.json` — всё машинночитаемо

## Ограничения (честно)

- Whisper и VLM работают на CPU: 3-минутное видео — минуты, часовое — десятки минут (и это
  по-прежнему бесплатно и не блокирует ваши задачи).
- VLM на 2–3 B параметров путается в мелких деталях — для важных кадров агент читает
  изображение сам (у него собственное зрение) и сверяет с подписью модели.
- GitHub Actions — общий сервис: очередь, лимит 6 часов на job, fair-use policy. Для
  «безлимита» это лучший публичный вариант, но не SLA.
